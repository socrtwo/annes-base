# Anne's Base

*Part of the Anne's Office suite: [Anne's Pen](https://github.com/socrtwo/QuillPen) (documents), [Anne's Grid](https://github.com/socrtwo/QuillGrid) (spreadsheets), [Anne's Post](https://github.com/socrtwo/QuillPost) (email), [Anne's Stage](https://github.com/socrtwo/QuillStage) (presentations), [Anne's Loom](https://github.com/socrtwo/QuillLoom) (web sites), [Anne's Press](https://github.com/socrtwo/QuillPress) (desktop publishing), [Anne's Folio](https://github.com/socrtwo/QuillFolio) (PDF), [Anne's Lens](https://github.com/socrtwo/QuillLens) (pictures) and **Anne's Base** (databases).*

An original, open-source desktop database for Android, iOS, Windows, macOS, Linux, ChromeOS and the web, in the tradition of Microsoft Access: tables, queries, forms, reports, macros and code in one file, for people who are not database administrators. Its goal is the same as the rest of the Anne's Office suite: **no missing commands**. Anne's Base gathers the commands of Access (including features Access has retired), of the classic database programs (dBASE, FoxPro and Visual FoxPro, Clipper, Paradox, FileMaker, Lotus Approach, Works, Q&A, R:BASE, DataEase, Alpha Four, HyperCard), of the open-source and server tools (LibreOffice Base, Kexi, SQLite, PostgreSQL, MySQL, SQL Server Management Studio, DBeaver, DuckDB) and of the web databases (Airtable, Notion, Quickbase, Power Apps), adds ideas of its own, and has an **AI** tab and menu for asking questions of your data, designing databases, writing queries and code, cleaning data and diagnosing damage. Every feature is a command, and every command can be put on the Quick Access Bar, on your own tab, in any classic menu layout, on a keyboard shortcut, in a macro, and found with command search. When a database is damaged, Anne's Base shows what it can recover instead of refusing to open it.

> **Status: M1 database editor with early M2 tools.** Native `.qbase` files support table creation and redesign, Text/Whole number/Decimal/Yes-No/Date fields, adding/editing/deleting records, CSV/JSON import, journaled history, selective record restore, sequential undo, browser autosave/restore and versioned snapshots. Any open database offers a read-only SQL view with query plans, export to CSV/tab/JSON/HTML/XML and a whole-database SQL script, and a relationships view. Other SQLite files open read-only. Production builds support installation and offline editing after the initial download. The browser app includes a sample database, command search, Word-style File menus, ribbon groups, classic menus, Quick Access pinning, customizable keyboard shortcuts and settings import/export. Query design, forms, reports, Access/xBase/Paradox files, damaged-file recovery and AI are not implemented. Tagged versions publish a web prerelease; no Android, iOS or desktop packages exist yet. The documents below describe the intended application; see [CONTRIBUTING.md](CONTRIBUTING.md).

## Run the preview

Install Node.js 24 LTS, then run from this repository:

```bash
# Termux: pkg install nodejs-lts python
npm ci
npm run dev
```

Open `http://localhost:5173` in your browser. Select **Try sample database**, then choose Customers or Orders in the navigation pane. Or choose **New blank database** and **Create table**: every table gets an automatic integer id, plus up to 32 Text, Whole number, Decimal number, Yes/No or Date fields. Yes/No fields accept Yes/No, True/False, On/Off or 1/0 and display Yes or No; Date fields store calendar dates as `YYYY-MM-DD`, and CHECK constraints keep both valid even for SQL written outside the editor. Required means non-null; empty text is a separate value. Use **Add record**, or select a row for **Edit selected** / **Delete selected**. **Undo last change** reverses the latest active change, including a deletion. **Change history** shows the latest 100 journal entries.

**Open SQLite file** reads a `.sqlite`, `.db` or `.qbase` from your device. **Download a copy** downloads a new file including the journal, never overwriting your source. Undo remains available after reopening the downloaded native file. File ▸ New/Open/Save/Close uses the same engine. Datasheet pages show up to 100 rows; use Previous/Next for more.

Select a row and choose **Record history**, or enter an id to inspect a deleted record. Choose a change to compare its **Before** and **After** values; **Load older changes** pages through histories longer than the global 100-entry overview. **Restore before values** / **Restore after values** writes a new journal entry without undoing unrelated records, and the restore can itself be undone. Empty text, NULL and an absent record are shown separately. Versions marked Undone can still be inspected and explicitly restored. History includes only changes actually recorded in the journal.

Automatic ids are not reused after deletion or undo within a table's lifetime. Selective restore is disabled if an older file reused an id or if the current row no longer matches its journal. It also rejects a stale history preview and cannot restore an old dropped table's rows into a new table of the same name. **Undo Delete** (Home ▸ Records or command search) lists the table's deleted records that are still missing, newest first, and restores any one with its original id as a new change that can be undone. **Show Table as of** (Data tab) rebuilds a read-only copy of the table at a chosen date and time since its current design by reversing later journal entries; undone changes are left out because the journal does not record when an undo happened. Related-record restoration, actor attribution and bulk restoration remain planned.

Use **Sort column** / **Sort direction**, **Filter column** / **Filter condition** / **Filter value**, or **Find in table**, then select **Apply view**. Find narrows the table to rows containing the literal term across text and number columns. **Add sort level** adds priorities (up to five columns); use **Move sort level … up** to reorder them. **Add filter condition** builds up to eight conditions, combined with **All conditions (AND)** or **Any condition (OR)**. Find is always combined with that whole group using AND. **Apply column filter** temporarily enables/disables the whole group while retaining its settings. Remove individual levels or conditions with their row buttons. The ribbon/menu commands Sort Ascending/Descending, Remove Sort, Advanced Sort, Filter, Advanced Filter/Sort, Apply/Toggle Filter, Clear All Filters and Find use the same controls. Sort Ascending/Descending changes the first priority while retaining the applied secondary levels; Remove Sort clears all levels. Clearing filters also clears Find but preserves sorting.

Numeric comparisons preserve signed 64-bit integer inputs. Text Contains/Find fold ASCII case and treat `%` and `_` literally, without wildcard syntax; full Unicode case folding is not provided. NULL is distinct from empty text and has its own filter conditions. Blob contents are not searched and support only NULL/not-NULL filtering. Sorting and comparisons follow SQLite's types/collations, with primary-key or full-row tie ordering for stable pages. The active view resets when switching tables or reopening a database; named browser presets can be loaded explicitly. Viewing never writes records or adds journal entries; saved query objects, nested condition groups and custom sort-value lists remain planned. Duplicate sort columns and invalid conditions leave the current view unchanged. These controls work with read-only SQLite files as well as native databases.

Use **Totals row** in the workspace, ribbon/menu or command search to show a footer under the datasheet. Each column can use **Count values**, **Minimum** or **Maximum** where supported; numeric columns also offer **Sum** and **Average**, and blob columns offer Count only. The matching-record count and all selected totals cover the **entire filtered result**, including rows beyond the current page. Count values ignores NULL; other totals show **—** when no non-NULL values remain. Find and the filter toggle affect totals in the same way as displayed records.

Integer totals retain exact values within SQLite's signed 64-bit range. An overflowing sum reports **Unavailable** instead of a rounded result, while other columns remain usable. Averages and floating-point sums are marked **≈**; they are approximate. Nonnumeric stored values in a numeric column are reported instead of silently counted as zero. Totals update after committed edits, undo and view changes, and exclude unfinished forms. Hiding/showing totals preserves the choices for the current table; switching tables or files resets them. Totals are read-only and are not saved in view presets or downloaded databases. **Standard deviation** and **Variance** use the sample (n − 1) formula, computed in two passes for accuracy, are marked ≈, and show — for fewer than two values. Grouping and saved totals settings remain planned.

**Saved views** below the table controls (also available through the Saved Views command) keeps named combinations of the applied sort levels, All/Any conditions, Find text and filter toggle. Choose **Apply view** before **Save applied view** to include control changes. Select a name and **Load saved view** to reuse it; loading is explicit and respects unfinished record forms. Change the name/settings and choose **Replace selected view** to rename or replace that preset. **Remove saved view** removes only the preset, leaving records and the active view intact. Wait for the saved confirmation before leaving.

Presets are a browser library, reusable across databases with the same table name, column names/order, declared types and primary-key positions. The originating file name is shown as a hint, not a database identity. A changed column layout disables loading/replacement; **Show views for other tables** lets you find and remove older presets. Names are unique within a layout (ignoring case), and stale-tab changes are rejected rather than overwritten. **Refresh saved views** picks up changes from other tabs. The library holds up to 200 presets. It contains filter values, belongs to this browser/profile/site, and is separate from downloaded databases, recovery copies and snapshots; clearing browser storage can remove it. It does not save rows, groupings, hidden fields or column order.

Editable native databases autosave committed changes and their journal as **Browser recovery copies** using IndexedDB. Wait for **Saved in this browser** before leaving, then restore a copy after reopening the app. Each database has its own copy; closing or creating another database does not delete it. **Recent Databases** in File opens this recovery list. You can remove inactive copies explicitly. Revision checks prevent a stale tab from overwriting or deleting a newer copy; a conflict leaves the local edits available to download or discard before restoring the latest copy.

Browser copies belong to this browser profile and site address (including the port). They do not update original files or sync between devices. They contain the latest committed database state, not unfinished form drafts or a versioned backup history. Browser storage can be unavailable, full, cleared or evicted, so keep downloaded backups. Failed autosaves remain visibly failed with a retry button, and pending changes/drafts retain their leave-page warning. A started download is not confirmation that the file was saved.

Use **Snapshots** in the workspace or File ▸ Info to keep several versions. **Create snapshot** saves the committed native database and journal under a label; manual versions stay pinned until removed. **Automatic snapshots before changes** is off by default. Enable it to capture the state before successful edits, undo and record restoration. Choose 1–20 automatic versions per database (default 5); older automatic versions are pruned atomically on the next automatic save. Rapid pending captures may be combined, so this is not a snapshot of every edit. The journal still records each change. Snapshot settings persist when browser preferences are available.

**Restore as new copy** verifies a SHA-256 checksum and SQLite integrity, then opens a separate database with a new recovery-copy id. Original snapshots and recovery copies are preserved, and the restored journal remains undoable. Clear **Current database only** to see versions of other databases, including after closing a file. **Download snapshot** verifies and downloads that version; **Remove snapshot** affects only the selected snapshot. Snapshot creation excludes unfinished drafts, and restoring respects pending-edit guards. Wait for the snapshot save message before leaving. Storage/checksum errors are visible and do not discard the open database. Snapshots need HTTPS or localhost for checksum support and share the browser-profile/site storage limits above; they are not embedded in downloaded databases or synced between devices.

Select a native table and choose **Design table** (or Design View, Add Field or Rename Field) to change an existing table: rename fields, reorder them with **Up**/**Down**, add fields (any type; they start empty), remove fields and change **Required**. Existing fields keep their type; to change a type, add a new field and remove the old one. Making a field required fails, with nothing changed, if any record lacks a value. **Save design** rebuilds the table in one transaction and journals it as a single change; removed fields' values are kept in the journal, so **Undo** restores the previous design and every removed value exactly. Record history starts again from the newest design, because older record images use a different field list; record ids are still never reused.

**SQL view** (also View ▸ SQL View, Create ▸ SQL Query and the Query commands) runs one `SELECT`, `WITH` or `VALUES` statement against the open database and shows up to 1,000 rows with exact 64-bit integers. It is deliberately read-only: data changes go through the journaled commands so they can be undone. The statement is checked before SQLite sees it (multiple statements, `PRAGMA`, `ATTACH` and other commands are refused), and SQLite's read-only query mode is verified as a second barrier. **Ctrl+Enter** runs, **Explain plan** (Ctrl+Shift+E) shows SQLite's query plan without running, **Format SQL** puts clauses on separate lines without altering literals, **Query history** keeps the last 50 statements for this page, and **Download results (CSV)** saves the shown rows. Queries run on the page's main thread, so an extremely slow query cannot yet be cancelled.

**Import data** (External Data ▸ Import Text/JSON) previews a CSV, tab-, semicolon- or bar-delimited file, or a JSON array of objects, as a new native table. Field types are inferred conservatively (codes with leading zeros and numbers beyond 64 bits stay Text) and can be changed before importing; empty values become NULL; duplicate names and `id` are renamed. The import is one journal entry, so **Undo** removes the table and all its records. Limits: 32 columns, 200,000 records, 32 MiB.

**Export** writes the current table, with its sort, filter and Find applied, as CSV, tab-delimited text, JSON (whole numbers keep every digit; Yes/No become true/false), an HTML table or XML; or the **whole database as a SQL script** that recreates user tables, indexes, views, triggers and rows in any SQLite database (generated columns are recomputed; the native journal is not included). **Relationships** lists the foreign keys declared in a SQLite file with a simple diagram; native tables cannot define relationships yet.

Commands with shortcuts in the catalog run from the keyboard when available (for example Ctrl+Z Undo, Ctrl+F Find, Ctrl+S download a copy, Alt+Q command search, Ctrl+Enter run query). In text boxes, typing and editing keys such as Ctrl+C keep their usual meaning, and keys for unavailable commands keep the browser's behavior. **File ▸ Options ▸ Customize Keyboard** assigns, moves, removes and resets shortcuts. **Export Settings** saves Quick Access pins, the menu layout and shortcuts as a JSON file; **Import Settings** validates and applies one. Custom ribbon tabs and portable mode remain planned.

This preview loads files into memory, with a **32 MiB input/recovery-copy limit**. Ordinary SQLite, old `0-preview` files, explicit read-only opens and unsupported native schemas remain read-only and are not automatically copied to browser storage. New native files use experimental catalog version `2-preview`, which includes selective-restore journal entries. Supported `1-preview` files remain editable and are marked `2-preview` atomically on their first selective restore. Creating a Yes/No or Date field, redesigning a table or importing marks a file `3-preview` in the same transaction; older builds open such files read-only. Original source files are never overwritten. Compatibility with future versions is not promised. Access files, encrypted databases, damaged-file recovery and redo are not supported.

The dev server listens on all interfaces for device testing. The modern ribbon opens a Word-style **File** screen with Home, New, Open, Info, Save, Print, Share, Export, Close and Options pages. Use **Back** or Escape to return to the workspace. Unimplemented actions remain disabled.

Command search covers all 693 planned commands; it searches labels, ids, groups and notes. Pin or unpin commands from search results, or use **Add All Choices** for the standard Quick Access set. Expand **Classic menus** below the ribbon to choose a historic layout; the default is Access 2003 style and its historical fidelity still needs verification. Pinning and menu layout are saved in browser storage when available. **Menus** / **Menu Layout** in command search, the View ribbon or Quick Access opens and focuses the layout chooser. In classic menus, use Left/Right between headings, Up/Down to enter and move through available choices, Home/End for first/last, and Right to enter a submenu. Left or Escape returns one level; Enter/Space activates the focused control. Type a name to jump to a matching choice; repeat a letter to cycle matches. Planned commands remain disabled and are skipped. Tab leaves the menu; activating a command or clicking/focusing elsewhere closes it. Menus preserve focus when an action opens a form or search field.

```bash
npm test             # engine, journal, SQL, import/export, keyboard and shell interactions
npm run build        # type check and production web build in dist/
python3 scripts/gen-plan.py --check
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the code that exists today. Capacitor, Electron, worker/OPFS storage and broader journal features remain upcoming M1 work.

Pushing a tag such as `v0.1.0-dev.1` that matches `package.json` runs the tests and build and publishes a GitHub prerelease with the zipped offline web build and its SHA-256 checksum (`.github/workflows/release.yml`). Unzip it and serve the folder from any static HTTPS host.

## Install and use offline

The **production web build** includes an installable manifest and a service worker. Serve `dist/` over HTTPS or localhost (for example, `npm run build` then `npm run preview`). Open it online once and wait for **Offline ready** at the bottom of the app. The complete editor, lazy code and SQLite WASM are saved together with integrity checks; then the same address can reopen and edit databases without a connection. The development server does not register a service worker. Installing does not provide a public hosting address or a native APK.

Use **Install app** when your browser offers it, or its **Install app / Add to Home Screen** menu. Availability depends on the browser and platform; installation is optional for offline use. HTTPS or localhost is required. A Termux server addressed as `localhost` qualifies, while a plain HTTP LAN address does not. Hosting under a subdirectory is supported; the manifest, worker and cache stay within that app address.

**Check for app updates** downloads a complete new version before offering it. The open editor never reloads automatically. When **App update ready** appears, save or cancel your forms, wait for browser saves or download a copy, then close **all** Anne's Base windows/tabs and reopen. A failed update leaves the previous offline version available. If offline files are missing, reconnect and use **Retry offline setup**. A newer deployment can prevent repair of an older version; in that case close all app windows and reopen online to complete its update.

Offline app files are separate from IndexedDB recovery copies and snapshots. Updating the app does not delete those databases. Storage still belongs to this browser profile and site address (including the port); changing the address or profile does not transfer your data. Clearing browser storage can remove offline files and databases. Keep downloaded backups. No cross-device synchronization, background database uploads or native platform packaging is included.

## The plan in brief

- **693 planned commands** in File, Home, Create, External Data, Database Tools, Data, Repair & Recovery, xBase, View, AI, Developer and Help, plus the contextual Table, Query, Form and Macro tabs. Each command records where the idea comes from; 129 are new ideas. See [docs/COMMANDS-PLAN.md](docs/COMMANDS-PLAN.md).
- **Classic menus as well as the ribbon.** The ribbon follows Access 2007 and later. View ▸ Menus adds a classic menu bar that defaults to **Access 2003** and can follow **dBASE III Plus ASSIST, the dBASE IV Control Center, FoxPro for DOS, Visual FoxPro, Paradox for DOS and for Windows, FileMaker Pro, Lotus Approach, Works, LibreOffice Base, SQL Server Management Studio or DBeaver**, all programs combined, or a **complete** layout with every command. See [docs/MENUS-PLAN.md](docs/MENUS-PLAN.md).
- **Access's keys and habits:** F11 navigation pane, F5 go to record, F9 and Shift+F9 refresh and requery, Ctrl+; date, Ctrl+' value from the previous record, Shift+Enter save record, F4 property sheet, F8 field list, Alt+F11 code editor, Ctrl+G Immediate window. FileMaker, FoxPro and SSMS key sets can be loaded instead.
- **One file, safe by default.** The native `.qbase` file is SQLite inside, with a write-ahead journal: every record change can be undone, deleted records can be brought back, any table can be viewed *as of* an earlier time, and automatic snapshots are kept. No 2 GB limit.
- **Opens what you already have:** Access `.accdb`, `.mdb` (Jet 3 and 4), `.accde`/`.mde` data, `.adp` forms and reports; dBASE, FoxPro and Clipper `.dbf` with memo and index files; Paradox; FileMaker exports; Approach, Works, Q&A and other historic formats; SQLite, DuckDB, LibreOffice Base `.odb`, SQL dumps, CSV, JSON, XML, spreadsheets, Parquet and GEDCOM; and live connections to PostgreSQL, MySQL/MariaDB, SQL Server, Oracle and Firebird. See [docs/FORMATS-PLAN.md](docs/FORMATS-PLAN.md).
- **Everything Access does, plus what it dropped:** table design with validation, lookups, calculated fields and data macros; the query grid and every query type, with SQL view; forms and reports with layout and design views, subforms, conditional formatting and grouping; labels and form letters through Anne's Pen; macros and a VBA-compatible Basic. Restored: the Database window, switchboards, PivotTable and PivotChart views, replication (as two-way sync), user-level security (as roles), and a successor to data access pages and web apps that publishes a database as a phone and browser app.
- **From the other programs:** the xBase **dot prompt**, work areas, `.prg` programs and PACK/ZAP/RECALL; Paradox **query by example** with example elements and ANSWER tables; FileMaker **Browse/Find/Layout/Preview modes**, portals, omit and constrain/extend found sets; Q&A's natural-language **Intelligent Assistant** with its taught vocabulary; Airtable and Notion **card, gallery, kanban, calendar, timeline and map views**, saved views and record comments; an SQL editor with plans, transactions, dialect translation and history from SSMS and DBeaver; Power Query-style **transform steps**.
- **Data quality and records work:** exact and near-duplicate finding with merge, address and free-text date standardization ("abt 1850"), outlier and type-mismatch reports, validation of existing data, a data profiler, test data, and GEDCOM import and export for family history.
- **AI tab and menu (optional):** Ask Your Data in plain English (always showing the SQL it ran and the rows, never an invented number), question to query, explain and improve SQL, design a database or a form from a description, suggest indexes and normalization, write and explain code, classify and extract fields from notes, match records across tables, turn scanned forms into rows, and **Diagnose with AI** for damaged files. By default only the schema is sent, never your data. See [docs/AI-PLAN.md](docs/AI-PLAN.md).
- **Database repair and recovery:** Compact and Repair as you know it, plus Diagnose File for files that will not open, Deep Repair that rebuilds into a new file from the readable pages, system-table and code-project repair, dBASE header and memo repair, Paradox block repair, recovery of deleted records from free pages, SQLite WAL and journal recovery, object recovery from text exports, and carving of tables out of disk images and backups. The original is never written. See [docs/RECOVERY-PLAN.md](docs/RECOVERY-PLAN.md).
- **Ideas new to desktop databases** are listed in [docs/INNOVATIONS.md](docs/INNOVATIONS.md#9-new-in-annes-base): record history and restore, undo delete with related records, find across the whole database, object version history, one migration wizard in and out of every program, phone preview of forms, and more.

## Platforms (planned)

Each release will have builds for **Android** (APK and AAB), **iOS/iPadOS** (an unsigned .ipa you sign with your Apple ID), **Windows** (installer for x64 or ARM, or portable), **macOS** (universal), **Linux** (AppImage or .deb for x64, arm64 and armv7l, which covers **Raspberry Pi OS**), **ChromeOS** (Android app, Linux app or web app) and the **web** (static files; offline-capable and installable). Server connections and ODBC need the desktop builds or the suite relay; everything else works everywhere. See [docs/ARCHITECTURE-PLAN.md](docs/ARCHITECTURE-PLAN.md) and [docs/ROADMAP.md](docs/ROADMAP.md).
